## 🎨 Темы и прозрачность

### Переключатель тем (dark / light) через Rofi

**Идея:** Rofi-меню по хоткею (`Super+Alt+T`?) с выбором «Tokyo Night Dark» / «Tokyo Night Day».

**План:**
1. Создать структуру `~/.config/themes/`:
   ```
   themes/
   ├── current -> dark          # симлинк на активную
   ├── dark/
   │   ├── palette.sh           # THEME_BG, THEME_FG, THEME_BORDER_*
   │   ├── colors.ini           # [colors] для Polybar
   │   ├── colors.rasi          # * { ... } для Rofi
   │   └── colors.toml          # [colors.*] для Alacritty
   └── light/
       └── (то же самое)
   ```
2. Подключить include в существующие конфиги:
   - Polybar: `include-file = ~/.config/themes/current/colors.ini`
   - Rofi: `@import "~/.config/themes/current/colors.rasi"`
   - Alacritty: `[general] import = [...]`
   - BSPWM: `source ~/.config/themes/current/palette.sh` в `bspwmrc`
3. Скрипт `theme-toggle.sh`:
   - Переключить симлинк `current`
   - `bspc wm -r` (BSPWM + обои)
   - `pkill -x picom && picom &`
   - `pkill -x polybar && launch.sh &`
   - `dunstctl reload`
   - `gsettings set org.gnome.desktop.interface color-scheme 'prefer-light'/'prefer-dark'`
   - `gsettings set org.gnome.desktop.interface gtk-theme 'Adwaita'/'Adwaita-dark'`
4. Rofi-меню выбора (2 пункта + отмена).

**Сложность:** средняя. ~1 вечер.

**Нюансы:**
- Picom и Polybar **перезапускаются** (нет сигнала reload) — на мгновение мигнут.
- Dunst перечитывает конфиг через `dunstctl reload`, без убийства.
- Rofi и Alacritty читают конфиг при каждом запуске — перезапуск не нужен.
- GTK-приложения (Thunar) подхватывают `gsettings` на лету.

### Переключатель прозрачности (on / off)

**Идея:** Отдельный тумблер через Rofi-меню: «Прозрачность: вкл / выкл».

**План:**
1. Два `picom.conf` (или symlink + sed):
   - `picom.conf` (непрозрачный) — текущий, `opacity-rule` закомментирован
   - `picom-transparent.conf` — с `opacity-rule = ["90:class_g = 'Alacritty'", "95:class_g = 'Thunar'", ...]`
2. Скрипт `transparency-toggle.sh`:
   - Определить текущее состояние (какой конфиг активен)
   - Переключить симлинк на `picom.conf`
   - `pkill -x picom && picom --config ... &`
   - Уведомление о смене
3. Хоткей + Rofi-меню.

**Альтернатива:** одна настройка `active_opacity` / `inactive_opacity` в `picom.conf` через `sed`. Но это грязнее — правила `opacity-rule` всё равно нужно менять.

**Сложность:** низкая. ~30 минут.

## ⌨️ Хоткей `Super+Alt+T` (Telegram + Proxy) — спорный момент

**Текущее состояние:** `Super+Alt+T` запускает `tg-ws-proxy & sleep 1 && flatpak run org.telegram.desktop &`.

**Проблема:** буква **T** логично ассоциируется с двумя разными вещами:
1. **Telegram** (как сейчас)
2. **Themes / Transparency** (в будущем — переключатели тем и прозрачности из разделов выше)

Оба варианта мнемоничны, но занимать одну и ту же комбинацию нельзя. Нужно решить **до** реализации тем, чтобы потом не ломать мышечную память.

**Варианты:**

| Комбинация | Что | Плюс | Минус |
|---|---|---|---|
| `Super+Alt+T` → Telegram (**сейчас**) | Telegram + Proxy | Уже привык, T = Telegram | Нельзя занять под Themes |
| `Super+Alt+T` → Themes | Переключатель тем | T = Themes, логично | Ломает текущую привычку |
| `Super+Alt+G` → Telegram | Telegram + Proxy | G = телеГрам (кириллица), свободно | Менее очевидно |
| `Super+Alt+M` → Telegram | Telegram + Proxy | M = Messenger | Конфликт с `Super+M` (Monocle) — сбивает |
| `Super+Alt+Shift+T` → Themes | Переключатель тем | T сохранён за Telegram, Themes получает Shift-вариант | Длинная комбинация |

**Решение (предварительное):**
- **Telegram остаётся на `Super+Alt+T`** — привычка дороже мнемоники.
- **Темы — на `Super+Alt+Shift+T`** или **`Super+Alt+Y`** (Y = «яркость/тема»?) — решить при реализации.
- **Прозрачность** — на отдельную комбинацию, например `Super+Alt+P` (P = прозрачность, P уже занят под PPD → перенести PPD на `Super+Alt+E`?).

**Статус:** требует решения перед реализацией тем. Не блокирует текущий релиз.

## 📝 Neovim в `install.sh`

**Идея:** добавить установку Neovim в `install.sh`, чтобы пользователь получал готовый редактор из коробки — с возможностью писать `nvim` в терминале и сразу работать.

**Проблема:** в Debian 13 Trixie версия Neovim в репозитории — **устаревшая** (обычно 0.9.x или ниже требуемой для LazyVim 0.11.2). Это значит, что пакет из `apt` не подойдёт для современных конфигов.

### Варианты

**A. `apt install neovim` (просто, но старое)**

Плюсы:
- Одна строка в `install.sh`
- Автоматические обновления через `apt`

Минусы:
- Версия может быть ниже 0.11.2 → LazyVim/AstroNvim не запустятся
- Пользователь получает «голый» nvim без конфига

**B. Neovim AppImage (актуальная версия, но вручную)**

Плюсы:
- Всегда последняя версия
- Не требует компиляции

Минусы:
- Нужно скачивать вручную (curl/wget)
- Нужен FUSE для запуска AppImage (на Debian 13 работает из коробки)
- Обновления — вручную (или через скрипт в `install.sh`)
- **Не хранить AppImage в репозитории** (десятки мегабайт, плохо для git) — скачивать при установке

**C. Своя сборка / форк (максимальный контроль)**

Плюсы:
- Полный контроль над версией и конфигом
- Можно включить свой LazyVim/AstroNvim-конфиг в репо

Минусы:
- Поддержка: каждый апстрим-апдейт Neovim/LazyVim — твоя головная боль
- Если сломается LazyVim — пользователь не поймёт, что делать
- Дублирование работы: LazyVim/AstroNvim уже поддерживаются сообществом

**D. Не ставить Neovim вообще**

Плюсы:
- Ноль сложности
- Пользователь ставит сам, как хочет (LazyVim, AstroNvim, kickstart, голый nvim)

Минусы:
- «Из коробки» нет редактора — только если пользователь поставит сам

### Рекомендация (предварительная)

**B + D: поставить `neovim` через AppImage в `install.sh` (вариант B), но конфиг не поставлять — пользователь клонирует LazyVim/AstroNvim сам.**

Почему:
- `install.sh` скачивает актуальный AppImage (не из репо, а с GitHub releases Neovim)
- Кладёт в `~/.local/bin/nvim`, `chmod +x`
- В README — короткая инструкция: «хочешь LazyVim? `git clone https://github.com/LazyVim/starter ~/.config/nvim`»
- **Своя сборка — нет.** Поддерживать форк LazyVim дольше, чем объяснить пользователю одну команду.

**Что нужно проверить перед реализацией:**
- Есть ли `fuse` в зависимостях (`install.sh` не ставит его сейчас)
- Куда класть AppImage (стандарт — `~/.local/bin/`)
- Обновлять ли AppImage автоматически при `install.sh` (если уже есть более старая версия)
- Проверка версии в `install.sh`: если стоит `nvim >= 0.11.2` — пропустить скачивание

**Статус:** обсудить после реализации тем (низкий приоритет, не блокирует).

## 🐛 Известные ограничения (не TODO, а «принято»)

- **Dunst: второе+ уведомление появляется без анимации.** Конфликт Picom `geometry` с логикой стека Dunst. Вернёмся после обновления Picom (13+).
- **`window-height` не парсится с унарным минусом.** Пишем `"0 - window-height"` вручную.
- **Celeron N4120: профиль `performance` в PPD недоступен.** Особенность платформы (TDP 6 Вт, пассивное охлаждение). В PPD доступны только `balanced` и `power-saver`. Если нужен `performance` — вручную через `cpufreq-set` (не сохраняется после ребута).
