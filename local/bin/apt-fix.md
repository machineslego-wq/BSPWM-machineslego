# apt-fix — починка APT после 404 Not Found

APT пытается скачать конкретную версию `.deb`, но её уже нет на зеркале.
Команда сбрасывает локальные индексы, заново их скачивает и чинит
незавершённые установки. Установленные пакеты и настройки не затрагиваются.

Команда: `local/bin/apt-fix` (после `link.sh` — `~/.local/bin/apt-fix`).

## Почему возникает 404

`trixie` (Debian 13) и другие активные ветки регулярно получают обновления
безопасности: старая версия пакета **удаляется с зеркала** и заменяется новой.
Например, в индексе было `libmbedtls21_3.6.5-0.1~deb13u1_amd64.deb`, а на
сервере остался только `3.6.6-...` или `3.6.7-3`.

APT хранит имена файлов в локальных индексах `/var/lib/apt/lists/`. Если они
устарели, `apt install` идёт по старому имени и получает `404 Not Found`.
`apt update` сам по себе помогает не всегда: индекс может остаться от другого
зеркала или скачаться не полностью.

## Что делает команда

| Шаг | Действие |
|---|---|
| 1 | `apt-get clean` — удаляет скачанные `.deb` из `/var/cache/apt/archives/` |
| 2 | удаляет индексы из `/var/lib/apt/lists/` |
| 3 | `apt-get update` с `Acquire::Retries=3` — скачивает свежие индексы |
| 4 | `apt-get -f install` — донастраивает зависшие пакеты |
| 5 | `apt-get install <пакет>` — если пакет указан |

## Использование

```bash
apt-fix                 # сброс кэша и списков + update + fix-broken
apt-fix gitg            # то же и установить gitg
apt-fix --dry-run gitg  # показать шаги, ничего не менять
apt-fix --yes gitg      # без вопросов
```

Без root команда сама попросит пароль через `sudo -v`. `--dry-run` работает
без root и только печатает план.

## Флаги

| Флаг | Смысл |
|---|---|
| *(без флагов)* | интерактивно: показать план, спросить подтверждение |
| `--dry-run`, `-n` | только напечатать команды |
| `--yes`, `-y` | не спрашивать подтверждение и передать `-y` в apt |
| `-h`, `--help` | справка |

Аргументы без флагов — имена пакетов для установки после починки.
Порядок флагов и пакетов не важен.

## Чего команда не делает

- **Не меняет `sources.list`** и не добавляет зеркала.
- **Не делает `purge` и `autoremove`.**
- **Не удаляет установленные пакеты специально.** Но `apt-get -f install`
  может разрешить зависимости по своему усмотрению — без `--yes` он покажет
  план и спросит, с `--yes` выполнит сразу.
- **Не трогает `/home` и дотфайлы.**

## Если 404 остался после apt-fix

1. **Проверить зеркало.** Если `deb.debian.org` отдаёт битые индексы, временно
   подключить другое зеркало:

   ```bash
   echo "deb http://ftp.de.debian.org/debian trixie main contrib non-free-firmware" \
     | sudo tee /etc/apt/sources.list.d/trixie-mirror.list
   sudo apt update
   ```

   После починки файл можно удалить.

2. **Поставить проблемные `.deb` вручную** со [packages.debian.org](https://packages.debian.org):

   ```bash
   sudo dpkg -i libmbedtls21_*.deb libmbedx509-7_*.deb
   sudo apt install gitg
   ```

3. **Проверить, что `apt update` не ругается на подписи и сеть.** Ошибки
   `Release`/`InRelease` лечатся обновлением ключей или сменой зеркала,
   а не сбросом списков.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `apt/dpkg уже занят` | дождаться `unattended-upgrades`/`apt`; проверить `fuser /var/lib/dpkg/lock-frontend` |
| `apt update` упал | индексы уже удалены; восстановить сеть и повторить `apt-fix` или `sudo apt update` |
| Нет `sudo` | запустить из-под root: `sudo -i`, затем `apt-fix` |
| Нужно только обновить индексы | `sudo apt update` (без сброса), либо `apt-fix --dry-run` для проверки плана |

## Проверка

```bash
apt-fix --dry-run
# затем
apt-fix --yes gitg
```

После успешного `apt update` в выводе не должно быть строк с `404`.
