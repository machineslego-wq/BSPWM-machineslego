# Neovim — шпаргалка

Минимальный конфиг под работу с одним файлом: слева дерево проекта
(neo-tree), справа — одно окно редактора. Вкладок нет: открываешь файл из
дерева — он **заменяет** тот, что был открыт. Плюс git-хунки (gitsigns) и
подсказки по коду (LSP + blink.cmp).

Всё, что не описано ниже как хоткей, — **стоковый Neovim**: конфиг не
переопределяет базовые команды (`:q`, `:w`, `<C-w>`, `:%s/...`), а только
добавляет дерево, git, LSP и несколько удобных клавиш.

Конфиг лежит в `config/nvim` (симлинк `~/.config/nvim`), плагины — `vim.pack`,
список только в `lua/plugins.lua`. Файлы по зонам: `options` (поведение),
`keymaps` (хоткеи), `explorer` (дерево), `git`, `lsp` + `completion`
(подсказки), `theme`, `treesitter`, `ui` (статуслайн).

## Как читать клавиши

| Запись | Что нажимать |
|---|---|
| `<leader>` | **Пробел** |
| `<C-l>` | **Ctrl + L** (латинская «эль») |
| `<C-w>h` | **Ctrl + W**, затем **H** |
| `:q` | набрать в командной строке `:q` и Enter |

Все хоткеи объявлены в одном файле — `lua/keymaps.lua`. Список ниже.

## Запуск и выход

| Действие | Команда |
|---|---|
| Открыть Neovim | `nvim` |
| Открыть файл | `nvim файл` |
| Сохранить | `<leader>w` или `:w` |
| Сохранить и выйти | `:wq`, `:x` или `ZZ` |
| Закрыть текущее окно | `:q` |
| Закрыть без сохранения | `:q!` |
| Выйти из всех окон | `<leader>q` или `:qa` |

## Одиночный буфер — главное отличие от стокового Vim

В стоковом Vim можно держать много буферов и переключаться между ними.
Здесь — **один файл за раз**. Никаких вкладок и `<leader>fb` нет.

- Открыл файл из дерева → он **заменил** предыдущий. Предыдущий при этом
  не остаётся «висеть» в списке как открытая вкладка.
- Если у предыдущего файла были несохранённые изменения, Vim **спросит**:

  ```
  Save changes to "file.txt"? [Y]es, [N]o, [C]ancel:
  ```

  `Y` — сохранить и открыть новый, `N` — выбросить изменения и открыть,
  `C` — отменить и остаться на месте.

- Этот вопрос дают `nohidden` + `confirm` (`options.lua`). В Neovim `hidden`
  по умолчанию включён — буфер молча прятался бы; в стоковом Vim без
  `confirm` вместо вопроса была бы ошибка `E37: No write since last change`.

Тот же вопрос появляется при `:q` и `:bd` с изменённым файлом.

## Дерево проекта (neo-tree)

Дерево заменяет встроенный `netrw` (то, что открывается по `:e` на каталог).
Открыть/свернуть — `<leader>e`.

| Действие | Клавиши |
|---|---|
| Открыть файл (заменяет текущий) | `Enter` |
| Открыть в вертикальном сплите | `s` |
| Открыть в горизонтальном сплите | `S` |
| Создать файл / папку | `a` / `A` |
| Переименовать | `r` |
| Удалить | `d` |
| Копировать / вырезать / вставить | `y` / `x` / `p` |
| Дублировать | `c` |
| Переместить | `m` |
| Обновить дерево | `R` |
| Показать скрытые файлы | `H` |
| Помощь по клавишам | `?` |
| Закрыть дерево | `q` |

Точки (`.git`, `.gitignore`) видны, файлы из `.gitignore` скрыты. Дерево
следует за открытым файлом.

## Окна: дерево ↔ редактор

Дерево и редактор — это два окна Neovim. Переключение между ними — через
`Ctrl + W` (стоковый Vim), плюс короткие клавиши:

| Действие | Клавиши | Стоковый аналог |
|---|---|---|
| В дерево (окно влево) | `<C-h>` | `<C-w>h` |
| В редактор (окно вправо) | `<C-l>` | `<C-w>l` |
| Окно ниже / выше | `<C-j>` / `<C-k>` | `<C-w>j` / `<C-w>k` |
| Следующее окно | `<C-w>w` | — |
| Только текущее окно | `<C-w>o` (или `:only`) | — |

Особенности (это не стоковое поведение, а настройка `explorer.lua`):

- Дерево зафиксировано на **32 колонки** (`winfixwidth`) — сплиты и ресайз
  его не раздувают.
- `:q` в окне редактора не ломает раскладку: справа сразу появляется пустая
  рабочая область, дерево остаётся 32 колонки. `:q` в этой пустой области
  закрывает Neovim. `:q` в дереве закрывает только дерево.
- В стоковом Vim единственное окно всегда занимает весь экран, поэтому
  «дерево 32 колонки» возможно только пока есть второе окно.

## Git (gitsigns)

Знаки на полях: `▎` — добавлено/изменено, `▏` — удалено. В стоковом Vim
ничего из этого нет.

| Действие | Клавиши |
|---|---|
| Следующий / предыдущий хунк | `]c` / `[c` |
| Застейджить хунк | `<leader>gs` |
| Сбросить хунк | `<leader>gr` |
| Посмотреть хунк | `<leader>gp` |
| Blame строки | `<leader>gb` |
| Diff текущего файла | `<leader>gd` |

## Код: LSP и подсказки

Серверы ставятся один раз вручную: `:Mason` (UI) или
`:MasonInstall <имя>`, включаются нативно (`vim.lsp.enable`). Список —
в `lua/lsp.lua`: `lua_ls`, `bashls`, `pyright`, `ts_ls`, `clangd`,
`rust_analyzer`, `jsonls`, `yamlls`, `html`, `cssls`,
`emmet_language_server`, `intelephense` (PHP). Go (`gopls`) отложен.

| Действие | Клавиши |
|---|---|
| К определению / объявлению | `gd` / `gD` |
| Ссылки / реализации | `gr` / `<leader>ci` |
| Документация (hover) | `K` |
| Переименовать | `<leader>rn` |
| Действия кода (code action) | `<leader>ca` |
| Форматировать | `<leader>f` |
| Диагностика строки | `<leader>cd` |
| Следующая / предыдущая ошибка | `]d` / `[d` |

«Реализации» живут на `<leader>ci`, а не на стоковом `gi`: `gi` оставлен
как есть (перейти к последней правке и войти в режим вставки) — это
удобная команда стокового Vim, её не теряем.

Диагностика — виртуальным текстом (`●`), подчёркиванием и знаками на полях.

### Автодополнение (blink.cmp)

В стоковом Vim дополнения нет — здесь оно из LSP, путей и слов буфера.

| Действие | Клавиши |
|---|---|
| Принять подсказку | `Tab` |
| Следующий / предыдущий вариант | `Down` / `Up` или `Ctrl+N` / `Ctrl+P` |
| Открыть меню вручную | `Ctrl+Space` |
| Скрыть меню | `Ctrl+E` |
| Прокрутить документацию | `Ctrl+B` / `Ctrl+F` |
| Сигнатура функции | `Ctrl+K` |

`Enter` подсказку **не** принимает — он переносит строку. Документация к
варианту показывается сама через 300 мс.

## Тема и синтаксис

- Подсветка — treesitter, парсеры ставятся при первом запуске.
- Тема — `tokyonight-night`: фон `#1a1b26`, текст `#c0caf5`. Дерево темнее
  (`#16161e`), статуслайн `#1f2335`.
- Дополнительный парсер: `:TSInstall <язык>`, обновление — `:TSUpdate`.

Для treesitter нужен `tree-sitter` CLI ≥ 0.26.1 (ставится
`scripts/install.sh` в `~/.local/bin/tree-sitter`).

## Плагины

Список — только `lua/plugins.lua`, менеджер — встроенный `vim.pack`.
Версии зафиксированы в `nvim-pack-lock.json` (руками не править).

| Действие | Команда |
|---|---|
| Обновить все плагины | `:lua vim.pack.update()` |
| Перезапустить после обновления | `:restart` |
| Проверить здоровье | `:checkhealth` |

Первый запуск требует сеть: `vim.pack` качает плагины, LSP-серверы ставятся
отдельно через `:Mason` (UI) или `:MasonInstall <имя>` в `~/.local/share/nvim/mason/bin`.

## Изменения конфига

Правка `config/nvim` сразу меняет `~/.config/nvim` (симлинк).

- Lua-модули применяются после перезапуска `nvim` (или `:source %` для
  текущего файла).
- Настройки плагинов лучше проверять перезапуском.

## Частые проблемы

| Симптом | Решение |
|---|---|
| Нет подсветки синтаксиса | `:TSUpdate`, проверить `tree-sitter --version` |
| LSP не подключился | `:checkhealth lsp`, `:Mason` |
| При открытии файла спрашивает про сохранение | Так и задумано (`confirm`): `Y` сохранить, `N` выбросить, `C` отменить |
| `:q` закрыл окно, но Neovim работает | Справа появилась пустая область. Выйти — `:q` в ней или `<leader>q` / `:qa` |
| Дерево нельзя растянуть мышью | Ширина зафиксирована (`winfixwidth`) |
| `<C-h>` не переключает в дерево | В некоторых терминалах Ctrl+H = Backspace; используй стоковый `<C-w>h` |
